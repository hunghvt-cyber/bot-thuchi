# Native bank copy-command controls — 24/10/2026

Owner approved replacing slow server-rendered submenus with four direct native copy buttons, accepting Paste as the extra step. Prior batching/read-only navigation still felt slow in real use. This change removes the backend round trip from selecting an edit action; applying a submitted command still waits for GAS/Sheets.

## Phone workflow

New bank drafts, confirmed original messages and fresh success receipts show Sửa tiền / Nội dung / Danh mục / Thu-Chi buttons with copy_text only, no callback_data. Each copies a command ending in a space, e.g. /suanoidung #b<12-hex event id> . User taps, pastes, adds the value and sends. No automatic filling or sending is claimed. Drafts retain Duyệt and Xóa nháp buttons because those change state. Recorded confirmations retain the four edit-copy buttons. No inline mode, BotFather setup, new host, new bot, token or MacroDroid import.

Commands: /suatien, /suanoidung, /suadanhmuc, /sualoai. Money is exact VND for bare/grouped integers, with existing k/tr shorthand; category must be one of the existing categories; type accepts Thu or Chi; description max 400. Missing/invalid values give examples/current category list and do not write. Copying alone does not approve or write. A submitted valid draft correction uses the existing owner-approved edit-to-commit function when complete; draft approval expiry remains 48h. Existing success receipts remain directly under the submitted input.

Bank command reference #b<12-hex event id> intentionally distinguishes draft/event references from normal permanent transaction IDs. Lookup requires one event and current configured owner/group, never arbitrary latest transaction. Unknown/expired/ambiguous references and unauthorized commands are consumed before normal ledger intake. Normal permanent-ID family commands are untouched. New bank copy commands work while the event log is retained (seven days); an unrecorded draft still cannot be approved after 48h. After the event is purged, normal /suanoidung #<permanent transaction code> etc. remain available; no vanished draft is recreated.

For already recorded bank events, copy commands update the existing matching active ledger row under ScriptLock and append the existing AuditLog, without appendRow on Transactions. Validate permanent id, group, payer and deletion status again; escape formula-like descriptions and retain exact amount parsing. State command IDs/monotonic message IDs plus initial edit IDs prevent replay/reordered requests from reverting newer commands. Scalar updates are retryable after ambiguous failure without creating another transaction. A failure after a Sheets update but before audit/state confirmation can leave an applied update with an uncertainty note; no exactly-once audit guarantee is claimed. Current learning fields update on confirmed commands; immutable initial/first-approval snapshots remain.

Owner-only /bankbuttons refreshes the newest retained applicable original message in place and links it from a fresh note, allowing immediate testing without a new bank notification. It does not mutate event properties or transactions. Existing older inline buttons continue supported; opening old Edit transitions that message to new copy controls. No bulk retrospective message edits occur automatically.

## Validation

120 Node mock/static tests pass (111 prior + nine command-control cases). New checks cover copy-only payloads/256-character limit, command webhook routing and exact VND draft commit without Reply, all four fields, incomplete/invalid/expired/unauthorized/forged commands, post-recording updates to one row with audit, replay and reordered-command protection, 3-day recorded edit vs expired/unrecorded/deleted cases, unknown/ambiguous references, and owner refresh without state/ledger writes. Legacy callback/receipt/parser tests still pass.

No live bank command/message/row was generated by the assistant. Native copy behavior is documented by Telegram, but actual phone rendering/clipboard workflow remains for user verification. Backend apply speed is not claimed instantaneous. Existing seven-day log limits, storage capacity guard, receipt/manual flows, Sheets schema and legacy Homepage remain unchanged.
